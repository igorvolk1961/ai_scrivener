# B4: не удаётся создать Catalog.Пользователи — подробности для консультации со специалистом

Дата: 2026-10-25

## 1. Контекст и цель

Этап B4 — заполнение демоданных (`CommonModule.АИС_ДемоДанные.Заполнить()`), вызывается из обработки
`DataProcessor.АИС_ЗаполнитьДемоДанные` (её форма вызывает `Заполнить()` при открытии).

Функция должна создать 4 демо-пользователей (ДЛ1, ДЛ2, Руководитель, Аудитор) в справочнике
`Справочник.Пользователи` (бизнес-пользователи 1С:Документооборот), затем продолжить заполнение
остальных демоданных (делегирование, виды документов, типы, шаблоны, обязанности, промпты).

**Блокер: любая попытка создать элемент `Справочник.Пользователи` программно — падает** с одной и той же
ошибкой, независимо от того, как именно создаётся элемент.

## 3. Точная ошибка

```
Ошибка заполнения демоданных: Поле объекта недоступно для записи (Пользователи)
{ai_scrivener ОбщийМодуль.АИС_ДемоДанные.Модуль(95)}:Пользователи = Новый Соответствие;
{ai_scrivener ОбщийМодуль.АИС_ДемоДанные.Модуль(67)}:Пользователи = СоздатьПользователей(Должности);
{ai_scrivener ОбщийМодуль.АИС_ДемоДанные.Модуль(20)}:Результат = ЗаполнитьВнутри();
{ai_scrivener Обработка.АИС_ЗаполнитьДемоДанные.Форма.Форма.Форма(6)}:Сообщить(АИС_ДемоДанные.Заполнить());
```

Текст ошибки «Поле объекта недоступно для записи (Пользователи)» — это **стандартное сообщение
платформы** (не наш текст), число в скобках — вероятно, имя затронутого метаданного-объекта
(`Справочник.Пользователи`).

Получено через: `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())` внутри `Попытка...Исключение`,
обёрнутого вокруг `ЗаполнитьВнутри()`.

## 4. Критически важная аномалия — результат диагностики маркерами

Чтобы исключить кеширование и понять, докуда реально доходит выполнение, в код были добавлены
маркеры — отдельная запись файла `/tmp/kilo/debug_<шаг>.txt` на каждом шаге (см. текущий код в
`src/CommonModules/АИС_ДемоДанные/Module.bsl`, процедура `Маркер`).

**Результат:** после `Пользователи = Новый Соответствие;` (создание пустого соответствия — первая
строка функции `СоздатьПользователей`, строка 95) должен сразу писаться маркер `03a_map_created` —
**он не появляется**. При этом маркеры `01_start` и `02_dolzhnosti_ok` (до этого момента) появляются
исправно.

То есть между успешным вызовом `СоздатьДолжности()` и первой же исполнимой строкой тела
`СоздатьПользователей` (создание пустого `Новый Соответствие`) выполнение останавливается — **в
месте, где физически нет операций записи в объекты базы**. Ошибка при этом по-прежнему указывает на
`Поле объекта недоступно для записи (Пользователи)`.

Это не укладывается в обычную модель «ошибка в конкретной строке BSL».

## 5. Что перепробовано (5 принципиально разных подходов — результат идентичен каждый раз)

1. **Прямое создание**: `Справочники.Пользователи.СоздатьЭлемент()` + `Объект.ФизЛицо = ...` +
   `.Записать()` — ошибка.
2. **Без ФизЛицо**: убрали присвоение `Объект.ФизЛицо` — та же ошибка (то есть ФизЛицо не было
   причиной).
3. **`ОбменДанными.Загрузка = Истина`** перед `.Записать()` (штатный способ 1С пропустить сервисную
   логику `ПередЗаписью` при программной загрузке) — та же ошибка.
4. **Комбинация** (3) + без ФизЛицо — та же ошибка.
5. **Официальный путь** — создание реальной `ПользовательИнформационнойБазы` +
   `Объект.ДополнительныеСвойства.Вставить("ОписаниеПользователяИБ", ...)`, точно как это делает
   сама 1С:ДО в `CommonModule.Пользователи.СоздатьАдминистратора()` (см.
   `/home/igorvolk/.edt-workspace/docmng_base/DocMng_2_1_38_11/src/CommonModules/Пользователи/Module.bsl`,
   строки 697–826) — та же ошибка, байт-в-байт.

Также проверено и исключено:

- **`УстановитьПривилегированныйРежим(Истина)`** вокруг всего вызова — не помогает.
- **«Безопасный режим» расширения** (флаг в Конфигураторе → Расширения конфигурации → столбец
  «Безопасный режим») — обязателен для того, чтобы вообще писался файл-результат (без него
  `Новый ЗаписьТекста(...)` в `/tmp` тоже тихо падает) — но даже при полностью снятом флаге ошибка
  создания пользователя сохраняется.
- **Кеш платформы по UUID базы** (`~/.1cv8/1C/1cv8/<uuid-каталоги>`) — подтверждено, что
  кеш переживает полную переустановку базы (restore из бэкапа + `LoadConfigFromFiles`), если не
  удалить его вручную; кеш очищался перед каждым из последних тестов — не повлияло на эту ошибку.
- **Чисто текстовые правки BSL внутри уже существующего модуля не подхватываются** при
  `LoadConfigFromFiles -Extension` поверх существующей базы — нужна полная переустановка (`rm -rf`
  базы + restore из чистого `.dt`-бэкапа + повторная загрузка) для гарантии, что новый код реально
  попал в базу. Это подтверждалось через `scripts/build/dump_extension.sh` + `grep` по
  задеплоенному `Module.bsl` перед каждым тестом.

## 8. Вопросы для специалиста по 1С:ДО / платформе

1. Что означает платформенная ошибка «Поле объекта недоступно для записи (<ИмяОбъекта>)» —
   это сообщение о нарушении прав на уровне поля объекта, или о чём-то другом (защищённый/вычисляемый
   реквизит, блокировка на уровне формы, конфликт транзакции)?
2. Может ли `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, вызванный в блоке
   `Попытка...Исключение` **тремя уровнями выше** реального места исключения, показывать line/module
   атрибуцию некорректно (например, атрибутировать к первой строке объемлющей функции вместо реальной
   строки)? Это объяснило бы аномалию из раздела 4.
3. Есть ли в 1С:ДО 2.1 дополнительный защитный механизм для `Справочник.Пользователи`
   (помимо `ПользователиСлужебный.ПользовательОбъектПередЗаписью`), который блокирует запись
   **до входа в BSL-код нашего общего модуля** — например, на уровне формы/компоновки/блокировки
   данных, активируемый уже при первом обращении к `Справочники.Пользователи` в сеансе без
   назначенного профиля доступа?
4. Может ли отсутствие профиля доступа у пользователя `Администратор` в этой демо-базе (см.
   отдельную, более раннюю проблему) блокировать запись в `Справочник.Пользователи` на уровне,
   который не ловится `УстановитьПривилегированныйРежим`?

# Баг-репорт: падение 1С:Предприятие при обработке RLS в правах роли расширения

## Окружение

| Компонент | Версия |
|---|---|
| Платформа 1С:Предприятие | 8.3.27.2342 (x86_64, Linux) |
| 1C:EDT | 2026.1.3+25 |
| Конфигурация | 1С:Документооборот (DocMng) 2.1.38.11, `compatibilityMode = 8.3.27` |
| Расширение | `ai_scrivener`, `ConfigurationExtensionPurpose = AddOn`, `configurationExtensionCompatibilityMode = 8.3.27` |
| ОС | Linux 6.8.0-147-generic (Ubuntu) |

## Краткое описание

Платформа аварийно завершается сигналом `SIGSEGV` (разыменование нулевого указателя) при обработке `restrictionByCondition` (ограничение доступа по условию / RLS) в правах роли, принадлежащей **расширению** конфигурации. Падение не зависит от текста условия — воспроизводится на синтаксически неверном, синтаксически верном и тривиальном условии без единой ссылки на другие объекты.

Падение воспроизводится двумя независимыми путями:

1. автоматическая загрузка расширения из файлов (`LoadConfigFromFiles -Extension`), в том числе через `1cedtcli export` + загрузку в Конфигураторе;
2. интерактивное редактирование той же роли в редакторе прав Конфигуратора.

## Шаги воспроизведения

1. Взять расширение конфигурации для 1С:Документооборот 2.1.38.11 (назначение `AddOn`, совместимость `8.3.27`).
2. В роли расширения задать право `Read` на любой объект расширения с ограничением доступа (`restrictionByCondition`), условие — произвольное, в т.ч. тривиальное (`Поле = ""`).
3. Загрузить расширение в файловую информационную базу:
   ```
   1cv8 DESIGNER /F<база> /N Администратор \
     /LoadConfigFromFiles <каталог_выгрузки> -Extension <имя_расширения> \
     -updateConfigDumpInfo /UpdateDBCfg
   ```
   — либо открыть эту роль в Конфигураторе и сохранить (Ctrl+S) после добавления того же условия через редактор ограничений доступа.

## Ожидаемый результат

Расширение загружается / роль сохраняется без ошибок.

## Фактический результат

Процесс `1cv8` завершается аварийно сигналом `SIGSEGV` сразу после открытия файла прав роли (`Ext/Rights.xml`), содержащего `restrictionByCondition`. Подтверждено `strace` — крах происходит непосредственно после `openat()` на этом файле, до перехода к следующему объекту расширения.

Пример из `journalctl -k` (два независимых запуска, разные PID, одинаковый адрес):

```
1cv8[1522991]: segfault at 0 ip 000076a3a0ef40ad sp 00007ffc4e08cd60 error 4 in basic.so[76a39ff49000+142d000] likely on CPU 15 (core 7, socket 0)
1cv8[1542299]: segfault at 0 ip 00007ba16faf40ad sp 00007ffce8cfb0d0 error 4 in basic.so[7ba16eb49000+142d000] likely on CPU 4 (core 4, socket 0)
```

Из `strace`:

```
--- SIGSEGV {si_signo=SIGSEGV, si_code=SEGV_MAPERR, si_addr=NULL} ---
```

Смещение в `basic.so` (`+142d000` от базы загрузки модуля) идентично во всех наблюдавшихся падениях — разыменование нулевого указателя, детерминированно воспроизводимое.

## Изоляция (что проверено отдельно)

| Условие теста | Результат |
|---|---|
| `restrictionByCondition` с ссылкой на несуществующее поле объекта | Падение |
| `restrictionByCondition`, синтаксически и семантически корректное | Падение, то же место |
| `restrictionByCondition` без единой ссылки на другие объекты метаданных (сравнение строк + параметр сеанса) | Падение, то же место |
| `restrictionByCondition` отсутствует в правах роли | Загрузка/сохранение проходит без ошибок |
| Загрузка через `LoadConfigFromFiles` (CLI/Конфигуратор без GUI) | Падение |
| Сохранение той же роли вручную в редакторе прав Конфигуратора | Падение |

Падение не зависит от содержимого условия, от способа внесения (автоматически или вручную) и от типа объекта, на который распространяется право.

## Сопутствующее наблюдение

Отдельно (не через RLS) падение также воспроизводится при простом выборе в редакторе прав роли некоторых объектов расширения — объектов, у которых есть реквизиты типа `CatalogRef` на справочники основной конфигурации. Возможно, тот же первопричинный дефект платформы (построение списка полей/ограничений для объекта расширения, ссылающегося за пределы расширения), но это не подтверждено отдельной изоляцией и приведено как сопутствующий факт, а не как отдельно доказанный баг.

## Временный обход

Не задавать `restrictionByCondition` в правах ролей расширения через метаданные. Эквивалентную фильтрацию доступа реализовывать в прикладном коде (BSL), на стороне форм/отчётов/списков.

# Негативные тесты доступа

Ручные сценарии для проверки ролей и RLS расширения на копии демо-базы. Это не автотесты: для прогона нужны лицензия 1С, платформа и заполненные демоданные.

> **Актуализация 2026-10-28:** `АИС_ДемоДанные` удалена; она больше не создаёт должности и пользователей. Базовый штат создаётся симулятором из `config/enterprise.json`; тестовые фикстуры ДЛ1/ДЛ2 и т.п. больше не создаются автоматически. Логины `ДЛ1`, `ДЛ2`, `Руководитель`, `Аудитор`, `Админ`, `БезРоли` — legacy-фикстуры; сценарии ниже требуют адаптации под фактических пользователей предприятия.

## Область и ограничения

- Проверяются роли и RLS расширения `ai_scrivener`, а не штатная модель прав Документооборота целиком.
- Роль по умолчанию у расширения отсутствует: пользователь без явной роли `АИС_*` не получает доступ к объектам расширения.
- Для A2 и A4 пользователь не должен иметь базовых ролей с полными правами. Иначе штатные права откроют доступ, и сценарий будет недействителен.
- A4 — интеграционная проверка: расширение не задаёт отдельный RLS на `ВнутренниеДокументы`; проверяется штатная адресация докладов и базовые права.
- Приоритет специфичной обязанности над общей — не проверка доступа; см. `tests/1c/test_obligations.md`.

## Подготовка

1. Применить расширение `.cfe` к копии демо-базы.
2. Создать пользователей: `ДЛ1`, `ДЛ2`, `Руководитель`, `Админ`, `Аудитор`, `БезРоли`.
3. Выдать только роли расширения: `ДЛ1`/`ДЛ2` — `АИС_ДолжностноеЛицо`; `Руководитель` — `АИС_ВышестоящееДолжностноеЛицо`; `Админ` — `АИС_АдминистраторСистемы`; `Аудитор` — `АИС_Аудитор`; `БезРоли` — без ролей расширения.
4. Выдать минимальные базовые роли, необходимые для входа и работы с задачами. Не назначать `Админ` и `Руководителю` базовые роли с полными правами.
5. Создать по одной задаче для `ДЛ1` и `ДЛ2` с записями `АИС_КонтекстЗадачИИ` и `АИС_СостоянияПлейсхолдеров`.
6. Убедиться, что при входе заполняется `ПараметрыСеанса.АИС_ТекущееДЛ`.

## Сценарии

### A1. ДЛ не видит задачу другого ДЛ

- Войти как `ДЛ1`.
- Открыть список задач и форму задачи `ДЛ2`.
- **Ожидаемо:** задача `ДЛ2` и связанные записи `АИС_*` недоступны; задача `ДЛ1` доступна.
- **Фактически (2026-10-25):** в списке «Задачи мне» видна только «Демо-задача ДЛ1» (Всего: 1). Но через общий поиск (Ctrl+Shift+F) по тексту «Демо-задача ДЛ2» задача находится и открывается полностью (видно «Кому: ДЛ2», «Автор: ДЛ2», активна кнопка «Записать и закрыть») — базовый объект `Задача.ЗадачаИсполнителя` не ограничен. Проверить видимость связанных записей `АИС_КонтекстЗадачИИ`/`АИС_СостоянияПлейсхолдеров` через UI не удалось — для них пока нет формы/списка, доступных обычному пользователю (нет интерфейса оркестрации, это задача более поздних этапов).
- **Статус:** [x] пройден, [ ] **не пройден**.
- **Причина:** ни одному демо-пользователю не назначен профиль доступа 1С:ДО (`ПрофилиГруппДоступа`) — похоже, без профиля штатная модель прав Документооборота не ограничивает видимость чужих задач. Это пробел в демоданных/настройке доступа, а не ошибка RLS самого расширения (`ai_scrivener` не задаёт отдельный RLS на `Задача.ЗадачаИсполнителя` — такой задачи в объёме B3 не было).

### A2. Администратор не видит содержание задач

- Войти как `Админ` (только `АИС_АдминистраторСистемы` + минимальные базовые права).
- Открыть `АИС_КонтекстЗадачИИ`, `АИС_СостоянияПлейсхолдеров`, `АИС_ЛистОжидания`, `АИС_ИсторияДействийИИ`.
- **Ожидаемо:** содержание задач недоступно; настройки `АИС_ПромптПараметры`, `АИС_ТипыДействий`, `АИС_РасписаниеТриггеров` доступны.
- **Фактически (2026-10-25):** команда «Все функции» недоступна ни для одной роли в этой сборке демо-базы (искали и у `Админ`, и у настоящего `Администратора` — нигде не нашли, похоже, не включена на уровне базы), поэтому напрямую открыть регистры/справочники через UI не удалось. Косвенные доказательства: (1) статический анализ `src/Roles/АИС_АдминистраторСистемы/Rights.rights` — роль не содержит прав `Read`/`View` ни на `АИС_КонтекстЗадачИИ`, ни на `АИС_СостоянияПлейсхолдеров`, ни на `АИС_ЛистОжидания`, ни на `АИС_ИсторияДействийИИ` (их там просто нет), при этом даёт `Read`/`View`/`Insert`/`Update` на `АИС_ПромптПараметры`/`АИС_ТипыДействий`/`АИС_ТипыТриггеров`/`АИС_ДолжностныеОбязанности`/`АИС_РасписаниеТриггеров`; (2) при входе как `Админ` список «Задачи мне» пуст (Всего: 0) — ни своих, ни чужих задач, утечки содержания через единственную доступную форму не произошло.
- **Статус:** [x] пройден (по статическому анализу прав + наблюдаемому поведению), [ ] не пройден.
- **Примечание:** при наличии базовой роли с полными правами сценарий недействителен. Отдельная находка: ни наше расширение, ни база не выставляют настроечные справочники (`АИС_ПромптПараметры` и т.п.) в обычную навигацию — им нужен отдельный пункт командного интерфейса (сейчас в `АИС_Сервис` есть только обработка заполнения демоданных), иначе ими некому пользоваться даже при наличии прав.

### A3. Аудитор читает аудит, но не пишет

- Войти как `Аудитор` (без базовых ролей на изменение документов).
- Открыть `АИС_ИсторияДействийИИ`; попробовать изменить запись.
- **Ожидаемо:** чтение доступно, запись запрещена.
- **Фактически (2026-10-26):** статический анализ `src/Roles/АИС_Аудитор/Rights.rights` — на `InformationRegister.АИС_ИсторияДействийИИ` заданы только `Read=true` и `View=true`; `Update`/`Insert`/`Delete` отсутствуют (по умолчанию `false`). Интерактивно не проверено (нет записей в `АИС_ИсторияДействийИИ` — аудит LLM-вызовов ещё не реализован, писать там через UI нечем).
- **Статус:** [x] пройден (по статическому анализу прав), [ ] не пройден.

### A4. Вышестоящее ДЛ видит только адресованные доклады

- Войти как `Руководитель` с минимальными базовыми правами.
- Открыть список `ВнутренниеДокументы` с видом «Доклад о срыве сроков».
- **Ожидаемо:** видны только доклады, адресованные этому руководителю; чужие доклады недоступны.
- **Фактически (2026-10-26):** вид внутреннего документа «Доклад о срыве сроков» в базе не существует, самих докладов тоже нет — эта функциональность относится к Этапам 4–9 (оркестрация, эскалация), ещё не реализована. Проверить сценарий не на чем.
- **Статус:** [ ] пройден, [ ] не пройден, [x] **не применимо пока (нет предмета проверки)**.
- **Примечание:** это проверка штатной адресации и базовых прав; отдельного RLS расширения на `ВнутренниеДокументы` нет. Вернуться к сценарию после реализации доклада о срыве сроков (см. `plans/remediation-plan.md`, волна 1, п. 2.9).

### A5. Пользователь без роли расширения не получает доступ

- Войти как `БезРоли`.
- Открыть любой объект `АИС_*`.
- **Ожидаемо:** доступ запрещён; ошибка прав доступа.
- **Фактически (2026-10-26):** поиск (Ctrl+Shift+F) по «Специфичная обязанность» (элемент `АИС_ДолжностныеОбязанности`, создаётся демоданными) — «По запросу ничего не найдено». Список задач при входе пуст. Проверено через веб-клиент (автономный сервер `ibsrv` + Playwright, `guides/runbook.md` §2.5).
- **Статус:** [x] пройден, [ ] не пройден.
- **Примечание:** роль по умолчанию у расширения отсутствует; защита срабатывает, как и ожидалось. Статический анализ подтверждает: ни у одного объекта `АИС_*` нет `defaultRoles`, базовые роли их не упоминают.

## Итог

Прогон выполнен 2026-10-26 на копии демо-базы (десктопный клиент для A1/A2 + веб-клиент через `ibsrv`/Playwright для A5, см. `guides/runbook.md` §2.5). Итог: A2, A3, A5 пройдены; A1 **не пройден** (задача другого ДЛ доступна через поиск — пробел в базовой модели прав Документооборота, не в RLS расширения; нужен профиль доступа для демо-пользователей); A4 не применим — нет реализованного вида документа «Доклад о срыве сроков». Автоматический прогон в CI не выполняется: для него нужны лицензия 1С, платформа и копия базы.

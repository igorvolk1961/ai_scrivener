# Негативные тесты доступа

Ручные сценарии для проверки ролей и RLS на демо-базе. Выполняются после применения расширения к копии демо-базы и заполнения демоданных.

## Подготовка

1. Применить расширение `.cfe` к копии демо-базы.
2. Создать пользователей: `ДЛ1`, `ДЛ2`, `Руководитель`, `Админ`, `Аудитор`, `БезРоли`.
3. Назначить роли: `ДЛ1`/`ДЛ2` — `АИС_ДолжностноеЛицо`; `Руководитель` — `АИС_ВышестоящееДолжностноеЛицо`; `Админ` — `АИС_АдминистраторСистемы`; `Аудитор` — `АИС_Аудитор`; `БезРоли` — без ролей расширения.
4. Создать по одной задаче для `ДЛ1` и `ДЛ2` с записями `АИС_КонтекстЗадачИИ` и `АИС_СостоянияПлейсхолдеров`.
5. Убедиться, что `ПараметрыСеанса.АИС_ТекущееДЛ` заполняется при входе.

## Сценарии

### A1. ДЛ не видит задачу другого ДЛ

- Войти как `ДЛ1`.
- Открыть список задач и форму задачи `ДЛ2`.
- **Ожидаемо:** задача `ДЛ2` и связанные записи `АИС_*` недоступны; задача `ДЛ1` доступна.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

### A2. Администратор не видит содержание задач

- Войти как `Админ`.
- Открыть `АИС_КонтекстЗадачИИ`, `АИС_СостоянияПлейсхолдеров`, `АИС_ЛистОжидания`, `АИС_ИсторияДействийИИ`.
- **Ожидаемо:** содержание задач недоступно; настройки `АИС_ПромптПараметры`, `АИС_ТипыДействий`, `АИС_РасписаниеТриггеров` доступны.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

### A3. Аудитор читает аудит, но не пишет

- Войти как `Аудитор`.
- Открыть `АИС_ИсторияДействийИИ`; попробовать изменить запись.
- **Ожидаемо:** чтение доступно, запись запрещена.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

### A4. Вышестоящее ДЛ видит только адресованные доклады

- Войти как `Руководитель`.
- Открыть список `ВнутренниеДокументы` с видом «Доклад о срыве сроков».
- **Ожидаемо:** видны только доклады, адресованные этому руководителю; чужие доклады недоступны.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

### A5. Специфичная обязанность выигрывает у общей

- На демоданных: у ДЛ есть общая обязанность и обязанность с `Характеристика = Авария`.
- Создать триггер с характеристикой `Авария`.
- **Ожидаемо:** выбирается специфичная обязанность; при её отсутствии — общая.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

### A6. Пользователь без роли расширения не получает доступ

- Войти как `БезРоли`.
- Открыть любой объект `АИС_*`.
- **Ожидаемо:** доступ запрещён; ошибка прав доступа.
- **Фактически:** не выполнено.
- **Статус:** [ ] пройден, [ ] не пройден.

## Итог

Все сценарии требуют ручного прогона на демо-базе после заполнения демоданных. Автоматический прогон в CI не выполняется: для него нужны лицензия 1С, платформа и копия базы.

# Детальный план Этапа 2 — «Метаданные и доступ»

Детализация чек-листа `docs/implementation_plan.md` §10 «Этап 2». Этап создаёт только структуру (метаданные, роли, демоданные) — бизнес-логика (общие модули, формы, регламентные задания) не входит и остаётся на Этапах 4–6.

## 1. Границы этапа

Входит: перечисления, справочники, регистры сведений, определяемые типы, расширение штатных объектов, роли, RLS, параметр сеанса, обработка демоданных, негативные тесты доступа.

Не входит: `АИС_ОркестраторЗадач`, `АИС_РазрешительПлейсхолдеров`, интеграции с LLM/RAG, формы и команды (кроме минимума, нужного для проверки RLS), регламентные задания (включая `АИС_ГенерацияТриггеровПоТаймеру` — заводится вместе с модулем-реализацией на Этапе 4–5, не раньше: пустое регламентное задание без существующей процедуры общего модуля не загрузится в рабочую базу).

## 2. Текущее состояние (`src/`) — на конец этой сессии

Все объекты из этого списка реально собраны через `scripts/build/export_extension.sh` (настоящий EDT CLI).

| Категория | Создано |
|---|---|
| Перечисления (8) | `АИС_СостоянияЗадач`, `АИС_СпособыЗаполнения`, `АИС_СостоянияРазделов`, `АИС_ВидыПлейсхолдеров`, `АИС_СтатусыПлейсхолдеров`, `АИС_ТипыЗапросовЛистаОжидания`, `АИС_ТипыИсточниковОжидания`, `АИС_СостоянияЗапросовОжидания` |
| Определяемые типы (3) | `АИС_АдресатЗапроса`, `АИС_РезультатЗадачи`, `АИС_ИсточникТриггера` |
| Справочники (7) | `АИС_ТипыДействий` (+ реквизит `ТипОбъекта`), `АИС_ТипыТриггеров`, `АИС_ПромптПараметры`, `АИС_ДолжностныеОбязанности`, `АИС_РазделыДокумента` (подчинён `ИсходящиеДокументы`), `АИС_ЛистОжидания`, `АИС_РасписаниеТриггеров` |
| Регистры сведений (4) | `АИС_КонтекстЗадачИИ`, `АИС_СостоянияПлейсхолдеров`, `АИС_НормативыИИ`, `АИС_ИсторияДействийИИ` |

Три объекта (`АИС_РазделыДокумента`, `АИС_ЛистОжидания`, `АИС_РасписаниеТриггеров`) изначально задумывались как регистры сведений, но стали справочниками: у регистра сведений нет ссылочного типа (`refType` в `producedTypes`), а на запись в каждом из них нужно ссылаться из других объектов. `АИС_НормативыИИ` и `АИС_ИсторияДействийИИ` остались регистрами — у них настоящий композитный ключ (пара реальных измерений) или природа журнала, без необходимости внешней ссылки.

Перечисление `АИС_СправочникШаблонов`, которое планировалось изначально, не создано — обнаружилось дублирование со штатным `Enums.ТипыОбъектов` (`ВходящиеДокументы`/`ИсходящиеДокументы`/`ВнутренниеДокументы`/`Файлы`), использован он.

## 3. Определяемые типы — итоговый состав

| Тип | Состав | Назначение |
|---|---|---|
| `АИС_ИсточникТриггера` | `CatalogRef.ВходящиеДокументы`, `CatalogRef.ВнутренниеДокументы`, `CatalogRef.ВидыБизнесСобытий` | откуда пришёл триггер; у «расписания», «произвольного события» и «внешнего запроса» нет естественного объекта-ссылки — не заполняется для них, это ожидаемо |
| `АИС_РезультатЗадачи` | `CatalogRef.ИсходящиеДокументы`, `CatalogRef.ВнутренниеДокументы` | ссылка на результат задачи; «доклад» и «отсутствие результата» не требуют отдельного члена типа |
| `АИС_АдресатЗапроса` | `CatalogRef.Пользователи`, `CatalogRef.Должности`, `CatalogRef.СтруктураПредприятия` | адресат запроса в листе ожидания |

Поля `Характеристика` и `ТребуемыйВидДокумента` у `АИС_ДолжностныеОбязанности` (§4) — **не** отдельные именованные определяемые типы: у каждого ровно один потребитель, составной тип объявлен прямо на реквизите (принцип Оккама).

## 4. Справочники — итоговые поля

### `АИС_ДолжностныеОбязанности`

| Поле | Тип | Обязательность |
|---|---|---|
| `Наименование` (`Description`) | строка | да |
| `Должность` | `CatalogRef.Должности` | да |
| `Текст` | строка (многострочная) | да |
| `ДатаУтверждения` | дата | да |
| `ТипТриггера` | `CatalogRef.АИС_ТипыТриггеров` | да |
| `ТипДействия` | `CatalogRef.АИС_ТипыДействий` | да |
| `Характеристика` | `CatalogRef.ВидыВходящихДокументов` (MVP; расширить составом при появлении второго случая, не раньше) | нет |
| `ТребуемыйВидДокумента` | составной тип на реквизите: `CatalogRef.ВидыИсходящихДокументов`, `CatalogRef.ВидыВнутреннихДокументов` | нет |
| `Приоритет` | число (по умолчанию 0) | нет |
| `Версия` | число | нет |
| `Активность` | булево | да |

Сопоставление (логика Этапа 5, не создана): специфичная обязанность (с совпавшей характеристикой) выигрывает у общей для той же пары; `Приоритет` разрешает конфликт только внутри одной группы специфичности.

### `АИС_ПромптПараметры`

`Код`, `ТекстПромпта` (`CatalogRef.ШаблоныТекстов`), `Модель`, `Температура`, `МаксимумТокенов`, `ОжидаемаяJSONСхема`, `Версия`, `Активность`.

### `АИС_РазделыДокумента`

Владелец: `Catalog.ИсходящиеДокументы`. Поля: `Раздел` (код), `Заголовок`, `Порядок`, `Обязательный`, `Формат`, `Источник`, `Файл` (`CatalogRef.Файлы`), `Версия`, `Хеш`, `Ответственный`, `Задача` (`TaskRef.ЗадачаИсполнителя`), `Статус` (`EnumRef.АИС_СостоянияРазделов`), `Подтвердил`, `ДатаПодтверждения`, `Комментарий`. Новая версия раздела — новый элемент, старый → `Устарел`.

### `АИС_ЛистОжидания`

`Задача`, `Плейсхолдер`, `ТипЗапроса` (`EnumRef.АИС_ТипыЗапросовЛистаОжидания`), `ТипИсточника` (`EnumRef.АИС_ТипыИсточниковОжидания`), `Адресат` (`DefinedType.АИС_АдресатЗапроса`), `Текст`, `ДатаОтправки`, `СрокОжидания`, `Состояние` (`EnumRef.АИС_СостоянияЗапросовОжидания`), `Ответ`, `ДатаОтвета`, `ЧислоПопыток`, `ОжидаемаяВерсия`, `ОжидаемыйХеш`, `СсылкаНаРаздел` (`CatalogRef.АИС_РазделыДокумента`).

### `АИС_РасписаниеТриггеров`

## 5. Расширение `АИС_ТипыДействий`

Реквизит `ТипОбъекта` (штатный `EnumRef.ТипыОбъектов`). Начальные значения для демоданных:

| Значение `АИС_ТипыДействий` | `ТипОбъекта` |
|---|---|
| `ПодготовитьИсходящийДокумент` | `ИсходящиеДокументы` |
| `ПодготовитьФрагментДокумента` | не заполняется |
| `ПодготовитьРаспоряжение` | `ВнутренниеДокументы` |
| `ПодготовитьДоклад` | `ВнутренниеДокументы` |
| `НайтиИнформацию` | не заполняется (текстовый ответ, не проект документа) |
| `ВыполнитьДействиеВнеСистемы` | не заполняется |
| `ВозобновитьОтложеннуюЗадачу` | не заполняется |

Начальные значения `АИС_ТипыДействий`/`АИС_ТипыТриггеров` создаются как обычные элементы справочника (демоданными/администратором), а не через платформенный механизм «Предопределённые»: формат его представления в файловом проекте расширения не подтверждён (ни один справочник в фактической базе его не использует), и FR-005 всё равно требует admin-расширяемости без кода.

## 7. Что осталось сделать на Этапе 2

### 7.1. Расширение штатных объектов

- ТЧ `АИС_Плейсхолдеры` в `ШаблоныВходящихДокументов`, `ШаблоныИсходящихДокументов`, `ШаблоныВнутреннихДокументов` — поля по `docs/implementation_plan.md` §5.3. Самый рискованный формат из оставшихся — расширение чужого (штатного) объекта табличной частью, формат пока не проверен на реальном примере.
- Доп. реквизиты `Справочник.ИсточникиДанных`: URL, JSON-схема ответа, таймаут.

### 7.2. Роли и доступ

Создать вместо `АИС_ОсновнаяРоль` пять ролей (`docs/implementation_plan.md` §5.8):

| Роль | Права |
|---|---|
| `АИС_АдминистраторСистемы` | чтение/запись справочников и регистров расширения, кроме содержания задач |
| `АИС_ДолжностноеЛицо` | штатные права на свои задачи; чтение/запись `АИС_*` только через RLS по своей задаче |
| `АИС_ВышестоящееДолжностноеЛицо` | то же + чтение докладов, адресованных ему |
| `АИС_Аудитор` | чтение `АИС_ИсторияДействийИИ` и отчётов, без права записи |
| `АИС_СервисныйПользователь` | права, нужные регламентным заданиям и HTTP-сервисам |

RLS на `АИС_*`: через ссылку на базовую задачу. Параметр сеанса `ТекущееДЛ` — в `УстановкаПараметровСеанса`, через `Пользователи`.

### 7.3. Обработка `АИС_ЗаполнитьДемоДанные`

1. 3–5 ДЛ: `Пользователи` + `ФизическиеЛица`, постоянная должность через `СведенияОПользователяхДокументооборот`.
2. Иерархия должностей.
3. Минимум одна запись `Catalogs.ДелегированиеПрав` — проверка объединения обязанностей при замещении.
4. 3 шаблона с заполненной ТЧ `АИС_Плейсхолдеры`.
5. Обязанности в `АИС_ДолжностныеОбязанности`: минимум одна общая (без `Характеристика`) и минимум одна специфичная (`Характеристика = Авария`, с `ТребуемыйВидДокумента`) — проверка, что специфичная выигрывает.
6. Значения `АИС_ТипыДействий.ТипОбъекта` по таблице §5.
7. Начальные `АИС_ПромптПараметры` под типовые промпты (`docs/raw_specification.md` §4.8.2, включая `КлассификацияПроизвольногоСобытия`), без реального вызова LLM.

### 7.4. Негативные тесты доступа

- ДЛ не видит задачу другого ДЛ.
- Администратор не видит содержание ни одной задачи.
- Аудитор читает `АИС_ИсторияДействийИИ`, не может писать.
- Вышестоящее ДЛ видит задачи подчинённых только в объёме адресованного доклада.
- Специфичная обязанность по характеристике выигрывает у общей на демоданных.

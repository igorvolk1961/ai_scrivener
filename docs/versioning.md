# Контроль версий расширения 1С

## 1. Источник истины

Источник истины — репозиторий Git и проект 1С:EDT в каталоге `src/`.

Рабочая база 1С (файловая или PostgreSQL) — это **тестовая среда**, а не источник кода. Изменения, сделанные в Конфигураторе, не попадают в Git автоматически.

```
src/ (Git) → export XML → загрузка в базу → проверка → .cfe
      ↑                                      │
      └──────── редактировать только здесь ─┘
```

## 2. Что версионируется

В Git хранятся:

- `src/` — `.mdo`, формы, BSL-модули расширения;
- `DT-INF/PROJECT.PMF` — привязка к базовому проекту;
- `.project`, `.settings`;
- документация, требования, скрипты, конфигурация RAG-сервиса.

В Git **не хранятся**:

- `.dt`, `.cf`, `.cfe`;
- `1Cv8.1CD` и каталоги файловых баз;
- том PostgreSQL и дампы данных;
- XML-выгрузки в `artifacts/`;
- лицензии `.lic` и `.env`.

Они исключены через `.gitignore` и проверяются хуком `forbid-1c-binaries`.

## 4. Рабочий цикл

1. Изменить расширение **только в EDT/репозитории**.
2. Проверить `make check`.
3. Синхронизировать `src` с рабочей копией EDT и выгрузить XML:

```bash
./scripts/build/export_extension.sh
```

По умолчанию скрипт синхронизирует `src` с проектом `ai_scrivener_build` в рабочей области EDT. Если вы открыли сам проект `ai_scrivener`, задайте `EDT_PROJECT=ai_scrivener`.

4. Загрузить XML в базу:

```bash
./scripts/build/load_extension.sh server   # PostgreSQL
./scripts/build/load_extension.sh file     # файловая база
```

5. Проверить расширение в Конфигураторе и прогнать сценарии.
6. Сохранить `.cfe` в Конфигураторе:
   - «Расширения конфигурации» → `ai_scrivener` → «Конфигурация» → «Сохранить конфигурацию в файл»;
   - артефакт: `artifacts/ai_scrivener-<версия>.cfe`.
7. Закоммитить только текстовые изменения.

Не редактируйте расширение в Конфигураторе как в основной среде. Если это всё же произошло, сразу выгрузите расширение в XML (`./scripts/build/dump_extension.sh`) и перенесите изменения в EDT, иначе база и Git разойдутся.

## 5. Пересборка тестовой базы

1. Восстановить `.dt` в чистую файловую или серверную базу.
2. Создать расширение `ai_scrivener`:
   - имя `ai_scrivener`;
   - префикс `АИС_`;
   - назначение `Дополнение`;
   - совместимость `8.3.27`.
3. Выполнить `./scripts/build/export_extension.sh`.
4. Выполнить `./scripts/build/load_extension.sh <mode>`.
5. Проверить `_extensionsinfo` и сценарии.
6. Собрать `.cfe`.

## 6. Проверка расхождений

Выгрузить расширение из EDT:

```bash
./scripts/build/export_extension.sh
```

Выгрузить расширение из базы:

```bash
./scripts/build/dump_extension.sh server
```

Сравнить каталоги:

```bash
diff -ru artifacts/extension-xml artifacts/base-extension-xml
```

Форматирование XML может отличаться, поэтому различия нужно смотреть по существу: состав объектов, реквизиты, формы, модули. Если в базе есть изменения, перенесите их в EDT и повторите export.

## 7. Релизы и теги

Рекомендуемая схема:

- `main` — стабильная ветка;
- feature-ветки для изменений;
- тег версии: `v0.1.0`, `v0.2.0`;
- к тегу прикладывать артефакты:
  - `.cfe`;
  - XML-выгрузку;
  - checksum `.dt`;
  - отчёт тестов.

Пример:

```bash
git tag -a v0.1.0 -m "Extension 0.1.0 for DocumentManagement PROF 2.1.38.11"
git push origin v0.1.0
```

## 8. PostgreSQL

Схема и данные PostgreSQL не версионируются в Git. Для данных используйте `pg_dump`:

```bash
docker exec deploy-postgres-1 pg_dump -U ai_scrivener -d ai_scrivener -Fc \
  > artifacts/ai_scrivener-$(date +%Y%m%d).dump
```

Для воспроизводимости достаточно:

- версии базы 2.1.38.11;
- checksum `.dt`;
- XML/`.cfe` расширения;
- версии платформы и EDT.

## 9. Автоматизация

| Скрипт | Назначение |
|---|---|
| `scripts/build/export_extension.sh` | синхронизация `src` → EDT-копия и выгрузка XML |
| `scripts/build/load_extension.sh` | загрузка XML в файловую или серверную базу |
| `scripts/build/dump_extension.sh` | выгрузка расширения из базы для сравнения |
| `scripts/git/check_extension_manifest.py` | проверка `Configuration.mdo` и `PROJECT.PMF` |
| `scripts/git/forbid_1c_binaries.sh` | запрет коммита `.cfe/.cf/.dt` |

Хуки подключены в `.pre-commit-config.yaml` и запускаются через `make check`.

## 10. Известные ограничения

- Назначение «Дополнение» не хранится в `src`; при пересоздании базы его нужно выставить вручную.
- `.cfe` пока собирается через Конфигуратор, а не скриптом.
- XML-выгрузка из EDT и из базы может отличаться форматированием; сравнение требует нормализации.
- Базовая конфигурация Документооборота не входит в репозиторий и поставляется отдельным архивом.

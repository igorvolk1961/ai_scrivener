# Вычитка документов

Опциональная двухуровневая проверка проектов документов: быстрая детерминированная и глубокая LLM-вычитка с квотами.

## 1. Назначение

Проверять проект документа перед согласованием и подписанием:

- заполненность плейсхолдеров;
- даты, суммы, номера, ссылки;
- обязательные разделы;
- орфографию, пунктуацию, грамматику;
- согласование падежей и спряжений;
- смысловые и логические несоответствия;
- противоречия между разделами;
- стиль и канцелярит.

Функция не заменяет ДЛ и не применяет исправления автоматически.

## 2. Два уровня

| Уровень | Что проверяет | LLM | Стоимость |
|---|---|---|---|
| **Быстрая** | плейсхолдеры, обязательные разделы, даты, суммы, номера, ссылки, формат, повторы, склонения через штатный модуль | нет | почти бесплатно |
| **Глубокая** | орфография, пунктуация, грамматика, стиль, смысл, логика, противоречия | да | дорого, по квоте |

Быстрая проверка запускается после генерации и перед подписанием. Глубокая — по кнопке и с показом остатка лимита.

## 3. Глубокие замечания

LLM возвращает только замечания с цитатой и позицией:

```json
{
  "findings": [
    {
      "quote": "в соответствии с приказом № 15",
      "type": "logic",
      "severity": "high",
      "message": "Приказ № 15 относится к другому подразделению",
      "suggestion": "Уточнить приказ или подразделение",
      "confidence": 0.82
    }
  ]
}
```

Правила:

- цитата обязана существовать в исходном тексте;
- если цитата не найдена — замечание отбрасывается;
- замечание не применяется автоматически;
- пользователь принимает или отклоняет каждое замечание;
- принятое замечание применяется детерминированной заменой;
- после применения запускается быстрая проверка.

## 4. Экономия

- быстрая проверка первой;
- LLM получает только то, что не проверяется детерминированно;
- вычитываются только изменённые фрагменты;
- кэш по хешу фрагмента;
- проверка по разделам;
- малая локальная модель для грамматики/стиля;
- сильная модель для смысла/логики;
- глубокая проверка перед подписанием, не после каждой генерации;
- при перегрузке локальной LLM — очередь или деградация до быстрой проверки.

## 5. Квоты

Пользователь видит страницы, не токены.

- администратор задаёт лимит страниц на период (например, 30 страниц/день);
- лимит может задаваться по роли, подразделению, пользователю;
- перед запуском показывается оценка: «Документ ≈ 8 страниц, останется 4»;
- быстрая проверка лимит не расходует;
- глубокая расходует;
- квота проверяется на сервере 1С;
- локальная LLM: квота защищает вычислительные мощности;
- внешняя LLM: квота защищает бюджет;
- период и дата сброса хранятся в регистре.

## 6. Данные

### `АИС_ПроверкиДокументов`

- документ, версия/хеш;
- режим: `Быстрая`, `Глубокая`;
- статус: `ВОчереди`, `Выполняется`, `Завершена`, `Ошибка`;
- страницы, токены;
- модель;
- дата начала/окончания;
- сводка, ошибка.

### `АИС_ЗамечанияПроверки`

- проверка, номер;
- тип: `Орфография`, `Пунктуация`, `Грамматика`, `Смысл`, `Логика`, `Стиль`, `Оформление`;
- важность: `Низкая`, `Средняя`, `Высокая`, `Критическая`;
- цитата, позиция;
- сообщение, предложение;
- уверенность;
- решение: `НеРассмотрено`, `Принято`, `Отклонено`;
- пользователь, дата.

### `АИС_ЛимитыВычитки`

- пользователь, период;
- лимит страниц, использовано страниц;
- лимит токенов, использовано токенов;
- дата сброса, активность.

### Перечисления

- `АИС_РежимыПроверки`;
- `АИС_ТипыЗамечаний`;
- `АИС_ВажностиЗамечаний`.

## 7. Интерфейс

В форме проекта документа:

- кнопка «Проверить»: «Быстро» / «Глубоко»;
- остаток лимита и оценка страниц;
- панель замечаний с фильтром по важности;
- переход к цитате;
- «Принять», «Отклонить», «Принять все безопасные»;
- undo;
- повторная быстрая проверка после изменений.

## 8. Локальная и внешняя LLM

- Локальная LLM предпочтительна для конфиденциальных документов.
- Внешняя LLM — только по политике организации.
- `АИС_ИнтеграцияСLLM` поддерживает несколько провайдеров и моделей.
- Выбор модели по типу проверки: грамматика/стиль — малая, смысл/логика — сильная.
- Для внешней LLM учитывается бюджет и правила передачи данных.

## 9. MVP

1. Быстрая детерминированная проверка.
2. LLM-вычитка грамматики/пунктуации/стиля по кнопке.
3. Замечания с цитатами и accept/reject.
4. Лимит страниц на пользователя в день.
5. Локальная LLM через OpenAI-совместимый endpoint.
6. Аудит и статистика.

Смысловая и логическая проверка между разделами — следующий этап.

## 10. Критерии приёмки

- быстрая проверка не расходует квоту;
- глубокая проверка блокируется при исчерпании квоты;
- пользователь видит остаток в страницах;
- замечания содержат цитату, которая есть в тексте;
- замечания не применяются автоматически;
- принятые замечания применяются и аудируются;
- после изменений можно запустить повторную проверку;
- при перегрузке локальной LLM есть очередь или деградация.

## 11. Риски

| Риск | Мера |
|---|---|
| Дорого | быстрая проверка, diff-only, кэш, квоты |
| Медленно | локальная модель, очередь, проверка по разделам |
| Галлюцинации | обязательная цитата, confidence, accept/reject |
| Утечка данных | локальная LLM или политика для внешней |
| Слепое доверие | замечания не применяются автоматически |
| Перегрузка локальной LLM | квоты, приоритеты, деградация |

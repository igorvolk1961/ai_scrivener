# Карта стейкхолдеров

Выделено из `docs/raw_specification.md` §3 («Роли и права доступа») и дополнено участниками процессов из `docs/process-diagrams.md` §1, чтобы получить полную карту, а не только модель ролей RBAC. Принцип доступа везде — need-to-know: доступ к пользовательским задачам и документам — штатная модель прав Документооборота; RLS расширения на объектах `АИС_*` выполняется через ссылку на базовую задачу.

## 1. Роли внутри расширения (RBAC)

| Роль | Интерес/цель | Доступ |
|---|---|---|
| **Должностное лицо (ДЛ)** | Выполнить свои задачи с минимальной ручной рутиной; сохранить контроль над итоговым документом. | Свои штатные задачи и документы, связанный ИИ-контекст. Редактирует проекты до отправки. Вводит результаты действий вне системы. |
| **Вышестоящее ДЛ** | Получать доклады и управлять подчинёнными; отдавать распоряжения. | Свои задачи и доклады подчинённых; может отдавать распоряжения (разовые и, через фиксацию расписания, периодические). Адресат докладов о срыве сроков — после обязательной проверки перед отправкой (`docs/design-decisions.md` §14). |
| **Администратор системы** | Поддерживать работоспособность расширения без доступа к содержанию чужих задач. | Объекты расширения (обязанности, типы действий, параметры промптов, нормативы ИИ), списки шаблонов и права на их редактирование, настройки, статистика. Не видит содержание задач ДЛ. |
| **Аудитор** | Обеспечить прослеживаемость действий ИИ для контроля/расследований. | Просмотр `АИС_ИсторияДействийИИ` и отчётов без права редактирования. |
| **Методолог / ответственный за шаблон** | Поддерживать актуальность и качество шаблонов документов. | Создание, проверка, утверждение и версионирование шаблонов через мастер шаблонов (`docs/template-factory.md`); не утверждает содержание задач. |
| **Программист 1С** | Технически согласовывать черновики шаблонов; вести организационную структуру по распоряжению Гендиректора. | Правка `Справочник.СтруктураПредприятия`, техническое согласование шаблонов; окончательное утверждение шаблона остаётся за автором документа; не принимает кадровых и производственных решений. |

## 2. Участники процессов вне RBAC расширения

Не являются пользователями расширения, но влияют на процесс или зависят от его результата (источник: `docs/process-diagrams.md` §1).

| Участник | Роль в процессе |
|---|---|
| **Делопроизводитель** | Регистрирует входящие и исходящие документы в 1С:Документооборот (AS-IS путь, частично автоматизируется триггерами). |
| **Коллеги / внешние адресаты** | Источники данных и ответов на запросы вне формальных ролей расширения — адресаты поручений, получатели исходящих документов. |

## 3. Системы и внешние зависимости

| Система | Роль |
|---|---|
| **1С:Документооборот** | Источник истины доменных данных: документы, задачи, права, бизнес-процессы, файлы. Расширение не создаёт параллельных сущностей. |
| **Расширение ai_scrivener** | ИИ-оркестрация, плейсхолдеры, лист ожидания, аудит — всё ИИ-специфичное. |
| **RAG-сервис (Qdrant + FastAPI)** | Поиск шаблонов и нормативного контекста; stateless, источник истины — 1С. |
| **DeepSeek** | Выбор шаблона, анализ причин срыва сроков, генерация текста документов. |
| **GigaChat** | Эмбеддинги для RAG-индексации и поиска. |
| **Локальная LLM** | Вычитка документов, предпочтительна для конфиденциальных документов (`docs/proofreading.md`). |
| **Внешние источники данных** | БД 1С (утверждённые запросы), другое ДЛ, внешний API, расчётный сервис — источники значений плейсхолдеров. |

# Vision & Scope

Выделено из `docs/raw_specification.md` §1 («Общие сведения») как самостоятельный артефакт системного анализа.

## 1. Видение (Vision)

Разрабатывается расширение конфигурации **1С:Документооборот ПРОФ 2.1.38.11** для интеллектуального помощника должностного лица (ДЛ). Помощник реагирует на события (триггеры), определяет необходимые действия в соответствии с должностными обязанностями ДЛ, находит и заполняет данные в шаблонах документов, генерирует проекты документов, распоряжений и докладов.

Расширение не заменяет Документооборот и не создаёт параллельные документы, задачи и справочники. Пользовательские сущности остаются штатными; расширение хранит только ИИ-специфичный контекст.

### Цели системы

- Автоматизировать подготовку проектов документов по триггерам.
- Снизить когнитивную нагрузку на ДЛ за счёт автоматического поиска данных.
- Обеспечить соблюдение нормативных сроков исполнения.
- Автоматически эскалировать ситуации срыва сроков с анализом причин.
- Обеспечить прослеживаемость всех действий ИИ-агента.

## 2. Границы (Scope)

### 2.1. Платформенные и технологические ограничения

- Платформа: 1С:Предприятие 8.3.27.
- Поставка: расширение `.cfe` для `ДокументооборотПРОФ` 2.1.38.11; базовая конфигурация не изменяется.
- СУБД: PostgreSQL (production) или файловая база (локальный учебный стенд).
- ОС сервера: Ubuntu 22.04/24.04 LTS. ОС рабочих мест: Windows 10/11 или Ubuntu 22.04/24.04 LTS.
- LLM: внешний OpenAI-совместимый API (DeepSeek — генерация; GigaChat — эмбеддинги); локальная LLM — для вычитки конфиденциальных документов.

### 2.2. Принципы границ модели данных

- Штатные объекты переиспользуются максимально: `Пользователи`, `ФизическиеЛица`, `Должности`, `СтруктураПредприятия`, `СведенияОПользователяхДокументооборот`, `ДелегированиеПрав`, `ВходящиеДокументы`, `ИсходящиеДокументы`, `ВнутренниеДокументы`, `Задача.ЗадачаИсполнителя`, `Файлы`.
- ИИ-специфичные объекты получают префикс `АИС_`; новые документы не создаются (подробная модель — `docs/data-model.md`).

### 2.3. Что вне MVP (выделено из `docs/implementation_plan.md` §1)

- Дообучение LLM на данных заказчика.
- Электронная подпись.
- Интеграция по email/телефонии как канал ввода.
- Промышленная HA-топология.
- Индексация конфиденциальных документов в RAG.
- Мобильный клиент.
- Коммерческая эксплуатация демо-стенда.

### 2.4. Допущения

- Разработка ведётся с использованием ИИ-помощника кодирования; спецификация (`docs/raw_specification.md`) — основной источник требований.
- Обучение/дообучение LLM на данных заказчика на первом этапе не планируется.
- Каналы связи вне системы (телефон, мессенджеры, email) — ручной ввод результатов ДЛ; голосовой ввод вне MVP (см. `reviews/critical-review.md` §5).
- Коммерческая лицензия на 1С:Документооборот и production-топология — вне учебного проекта (`docs/design-decisions.md` §13).

## 3. Поэтапное раскрытие границ

Полный план этапов — `docs/implementation_plan.md` §10. Кратко:

| Этап | Граница |
|---|---|
| 0 | Мастер шаблонов — без него шаблоны не масштабируются |
| 1 (MVP) | «Входящий документ → проект исходящего», без внешних источников и эскалации |
| 1.5 | Вычитка документов (быстрая + глубокая по кнопке) |
| 2–3 (спецификация) / 8–9 (план) | Внешние источники данных, лист ожидания, расчётные сервисы, эскалация |
| 4 (спецификация) / 10 (план) | Полнота: распоряжения, доклады, произвольные события, RAG-извлечение значений, ACL |

## 4. Критерии приёмки системы в целом

Полный список — `docs/raw_specification.md` §8. Ключевые пункты:

- ИИ корректно выбирает шаблон в ≥90% случаев на выборке из 50 сценариев.
- ИИ корректно заполняет плейсхолдеры из БД в ≥95% случаев.
- Все действия ИИ воспроизводимы по `АИС_ИсторияДействийИИ`.
- Система стабильно работает при 100 активных задачах; отклик UI ≤2 секунд.

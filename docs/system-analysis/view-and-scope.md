# Vision & Scope

Выделено из `docs/raw_specification.md` §1 («Общие сведения») как самостоятельный артефакт системного анализа.

## 1. Видение (Vision)

Разрабатывается расширение конфигурации **1С:Документооборот ПРОФ 2.1.38.11** для интеллектуального помощника должностного лица (ДЛ). Помощник реагирует на события (триггеры), определяет необходимые действия в соответствии с должностными обязанностями ДЛ, находит и заполняет данные в шаблонах документов, генерирует проекты документов, распоряжений и докладов.

Расширение не заменяет Документооборот и не создаёт параллельные документы, задачи и справочники. Пользовательские сущности остаются штатными; расширение хранит только ИИ-специфичный контекст.

Целевая система — не «свободный генератор документов», а помощник, который собирает документ по шаблону. Шаблон задаёт структуру и плейсхолдеры, а для каждого плейсхолдера — источник и правила поиска: тип документа, период, автора, доступ, связи и другие фильтры. Вместо жёстких ссылок между полями документов используется гибридный поиск по корпусу; фильтры играют роль ограничителей. Это снижает хрупкость классических шаблонов 1С:ДО, которые требуют строго структурированных документов и жёстких привязок «поле → поле».

Текущий проект — MVP на пути к этой целевой системе. Он решает две промежуточные задачи: получить рабочий RAG (в перспективе — агентский RAG) и накопить большой корпус документов, на котором можно отработать целевую технологию. Свободная генерация агентом и временное автоодобрение нужны для ускоренного накопления синтетического корпуса; в целевой системе автоодобрения быть не должно, а контроль человека сохраняется.

### Цели системы

- Автоматизировать подготовку проектов документов по триггерам.
- Снизить когнитивную нагрузку на ДЛ за счёт автоматического поиска данных.
- Обеспечить соблюдение нормативных сроков исполнения.
- Автоматически эскалировать ситуации срыва сроков с анализом причин.
- Обеспечить прослеживаемость всех действий ИИ-агента.

## 2. Границы (Scope)

### 2.1. Платформенные и технологические ограничения

- Платформа: 1С:Предприятие 8.3.27.
- Поставка: расширение `.cfe` для `ДокументооборотПРОФ` 2.1.38.11; базовая конфигурация не изменяется.
- СУБД: PostgreSQL (production) или файловая база (локальный учебный стенд).
- ОС сервера: Ubuntu 22.04/24.04 LTS. ОС рабочих мест: Windows 10/11 или Ubuntu 22.04/24.04 LTS.
- LLM: внешний OpenAI-совместимый API (DeepSeek — генерация; GigaChat — эмбеддинги); локальная LLM — для вычитки конфиденциальных документов.

### 2.2. Принципы границ модели данных

- Штатные объекты переиспользуются максимально: `Пользователи`, `ФизическиеЛица`, `Должности`, `СтруктураПредприятия`, `СведенияОПользователяхДокументооборот`, `ДелегированиеПрав`, `ВходящиеДокументы`, `ИсходящиеДокументы`, `ВнутренниеДокументы`, `Задача.ЗадачаИсполнителя`, `Файлы`.
- ИИ-специфичные объекты получают префикс `АИС_`; новые документы не создаются (подробная модель — `docs/data-model.md`).

### 2.3. Границы MVP и целевой системы (2026-11-18)

**Текущий MVP:** ИИ-агент должностного лица — очередь запусков, шаги через `agent-service`, инструменты с allowlist, approval и временное автоодобрение, история действий с атрибуцией пользователя, настройки агента и триггеров; ответы по базе знаний и документам через RAG, поиск образцов через `search-service`, папки документов, административные экраны. Для накопления корпуса используется свободная генерация агентами и синтетические документы; автоодобрение ускоряет этот процесс и не является целевым режимом.

Триггеры MVP: документ (внутренний или внешний — для расширения это одно событие, различается только атрибут источника) и задача, в том числе поставленная самому себе. Третий тип — регламентное событие (таймер) на основе должностных обязанностей — в MVP не реализован.

Вне MVP:

- целевые шаблоны с плейсхолдерами и поиском по корпусу с фильтрами;
- регламентный триггер по должностным обязанностям;
- мастер шаблонов, автогенерация правил и сравнение шаблонов;
- глубокая LLM-вычитка и квоты;
- дообучение LLM на данных заказчика;
- электронная подпись;
- интеграция по email/телефонии как канал ввода;
- промышленная HA-топология;
- индексация конфиденциальных документов в RAG;
- мобильный клиент;
- коммерческая эксплуатация демо-стенда.

### 2.4. Допущения

- Разработка ведётся с использованием ИИ-помощника кодирования; спецификация (`docs/raw_specification.md`) — основной источник требований.
- Обучение/дообучение LLM на данных заказчика на первом этапе не планируется.
- Каналы связи вне системы (телефон, мессенджеры, email) — ручной ввод результатов ДЛ; голосовой ввод вне MVP (см. `reviews/critical-review.md` §5).
- Коммерческая лицензия на 1С:Документооборот и production-топология — вне учебного проекта (`docs/design-decisions.md` §13).
- Симулятор предприятия — внешний инструмент разработки и проверки, а не часть продуктовой поставки; его контур и ограничения описаны в `plans/2026-10-26-enterprise-simulator.md`.

## 3. Поэтапное раскрытие границ

Полный план этапов — `plans/implementation_plan.md` §10. Кратко:

| Этап | Граница |
|---|---|
| 0 | Локальный стенд и метаданные расширения |
| 1 | Вопрос по базе знаний → RAG → ответ LLM с цитатами |
| 2 (текущий MVP) | ИИ-агент: очередь запусков, agent-service, инструменты, approval и временное автоодобрение, история, настройки и триггеры, RAG по документам и образцам, синтетический корпус |
| Целевая (post-MVP) | Шаблоны с плейсхолдерами и поиском с фильтрами, агентский RAG, регламентные триггеры, обязательный approval без автоодобрения |
| Post-MVP: шаблоны | Мастер шаблонов, автогенерация правил, сравнение шаблонов |
| Post-MVP: вычитка | Быстрая + глубокая вычитка по кнопке |
| Post-MVP: источники | Внешние источники данных, лист ожидания, расчётные сервисы, эскалация |
| Post-MVP: полнота | Распоряжения, доклады, произвольные события, RAG-извлечение значений, ACL |

## 4. Критерии приёмки системы в целом

Для текущего MVP критерии retrieval/answer уточняются в `plans/2026-11-04-effective-rag.md` (retrieval + answer + citations + no-answer), а контур агента — в FR-063–FR-070. Критерии выбора шаблонов и заполнения плейсхолдеров ниже относятся к post-MVP.

Полный список — `docs/raw_specification.md` §8. Ключевые пункты:

- ИИ корректно выбирает шаблон в ≥90% случаев на выборке из 50 сценариев.
- ИИ корректно заполняет плейсхолдеры из БД в ≥95% случаев.
- Все действия ИИ воспроизводимы по `АИС_ИсторияДействийИИ`.
- Система стабильно работает при 100 активных задачах; отклик UI ≤2 секунд.

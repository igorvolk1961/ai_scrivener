# Глоссарий

Выделено из `docs/raw_specification.md` §2 как самостоятельный артефакт системного анализа. Источник истины термина — здесь; остальные документы используют термины в этом значении без повторного определения.

| Термин | Определение |
|---|---|
| **ДЛ** | Должностное лицо — `Пользователь` с привязкой к `ФизическомуЛицу`, занимающий одну постоянную должность и, опционально, замещающий одну или несколько других (`docs/raw_specification.md` §4.1.3). |
| **Должность** | Штатная единица с набором обязанностей и местом в иерархии (`Справочник.Должности`). |
| **Действующие должности ДЛ** | Объединённый на дату набор: постоянная должность (`СведенияОПользователяхДокументооборот`) ∪ должности всех, кого ДЛ замещает на эту дату (`ДелегированиеПрав`). Обязанности резолвятся по этому набору, источник отдельной должности (постоянная/замещаемая) не важен. |
| **Замещение** | Исполнение обязанностей другой должности на период — не новый объект расширения, а штатный механизм делегирования прав Документооборота (`Catalogs.ДелегированиеПрав`). |
| **Должностные обязанности** | Формализованное описание действий ДЛ в различных ситуациях (`АИС_ДолжностныеОбязанности`), привязанное к паре (`ТипТриггера`, `ТипДействия`) для каждой действующей должности. |
| **Триггер** | Событие, требующее реакции ДЛ (входящий документ, таймер, распоряжение, бизнес-событие, ответ на запрос, истечение срока ожидания). |
| **Распоряжение** | Триггер и одновременно возможный прямой источник требуемого действия: указание вышестоящего ДЛ, письменное или устное (зафиксированное при регистрации как `ВнутреннийДокумент`), которое может задавать разовое действие или — через фиксацию в `АИС_РасписаниеТриггеров` — периодическое требование по таймеру. |
| **Плейсхолдер** | Именованный фрагмент шаблона документа, подлежащий заполнению данными. |
| **Источник данных** | Место, откуда берётся значение для плейсхолдера: БД документов, расчётный сервис, внешний API, другое ДЛ как держатель сведений. Решение ДЛ — отдельный способ заполнения, а не источник данных. |
| **Лист ожидания** | Справочник `АИС_ЛистОжидания` (не регистр сведений — нужен ссылочный тип) — незаполненные плейсхолдеры и неподтверждённые разделы, по которым отправлены запросы. |
| **Решение ДЛ** | Способ заполнения плейсхолдера (`РешениеДЛ` в `АИС_СпособыЗаполнения`), отличный от запроса факта: ДЛ формулирует управленческое решение, видя прецеденты, а не просто сообщает известное значение. |
| **Задача реагирования** | Штатная `Задача.ЗадачаИсполнителя` плюс запись `АИС_КонтекстЗадачИИ`. |
| **Эскалация** | Автоматическое формирование доклада о срыве сроков с анализом причин; направляется вышестоящему ДЛ после обязательной проверки (см. `docs/design-decisions.md` §14). |
| **АИС_** | Префикс объектов расширения; в проекте — «Автоматизированная интеллектуальная система» (AI Scrivener). |

## Термины корпуса знаний

Термины введены планом `plans/1793687400076-knowledge-corpus-storage.md`.

| Термин | Определение |
|---|---|
| **Корпус знаний** | Совокупность скачанных материалов и их метаданных, переживающая сброс ИБ; в плане — внешний каталог `corpus_dir` с блобами, манифестом и снапшотами. |
| **CAS-хранилище** | Content-addressed storage: адрес объекта вычисляется из его содержимого. В проекте адрес — SHA-256, путь `blobs/sha256/ab/cd/<sha256>`; одинаковые файлы хранятся один раз. |
| **Блоб** | Файл в CAS, адресуемый хешем своего содержимого; не перезаписывается, новое содержимое даёт новый адрес. |
| **Материал** | Физический файл в корпусе, уникальный по `sha256`; карточка `АИС_МатериалыЗнаний` — одна строка на файл, без сотрудника и задачи. |
| **Загрузка материала** | Факт скачивания материала сотрудником по задаче и источнику; карточка `АИС_ЗагрузкиМатериалов`. У одного материала может быть несколько загрузок. |
| **Манифест корпуса** | Append-only `manifest.jsonl` с провенансом по каждому блобу; не содержит рубрик и не переписывает байты. |
| **Провенанс** | Метаданные происхождения материала: источник, автор/орган, дата публикации и загрузки, лицензия, сотрудник, задача. |
| **Снапшот корпуса** | Зафиксированный срез манифеста и хешей (`snapshots/run-*`) для воспроизводимого повторного прогона и импорта. |
| **Аннотации рубрик** | Append-only `annotations.jsonl` по `sha256` для будущей рубрикации; в плане хранения только зарезервированы и не создаются. |
| **GC корпуса** | Сборка мусора mark-and-sweep: удаление блобов, на которые нет ссылок в манифесте, аннотациях, снапшотах и отчётах; выполняется явно, по умолчанию `--dry-run`. |
| **Идемпотентный импорт** | Материал — upsert по `sha256`; загрузка — upsert по `(sha256, source_url, employee, task_id)`. Повтор обновляет запись, но не создаёт дубль. |
| **Офлайн-режим** | Режим этапа 3 симулятора: поиск и скачивание только по корпусу и `retrieval_events`, без сетевых вызовов. |
| **Матрица отказов** | Таблица «отказ → обнаружение → восстановление → потеря»; используется для проверки надёжности корпуса и импорта. |

## Термины RAG и поиска

Термины введены при обсуждении качества RAG; используются в `rag-service`, `reviews/critical-review.md` §3 и `docs/design-decisions.md` §18.

| Термин | Определение |
|---|---|
| **Эмбеддинг** | Числовой вектор фиксированной размерности, представляющий смысл текста; в проекте — GigaChat `EmbeddingsGigaR`, 2560 измерений. Близость векторов измеряется косинусным сходством. |
| **Чанк** | Фрагмент документа, который индексируется и ищется как отдельная единица. В текущей реализации — до 1000 символов с перекрытием 150; целевая реализация — по структурным границам. |
| **Чанкинг** | Разбиение текста на чанки. Сейчас — фиксированная длина по символам (`chunk_size_chars`), что рвёт пункты, таблицы и списки; целевой вариант — абзац/пункт/элемент списка с ограничением максимальной длины. |
| **Перекрытие (overlap)** | Повторяющаяся часть соседних чанков, сохраняющая смысл на границе; параметр `chunk_overlap_chars` (150). Само по себе не устраняет дублирование в выдаче. |
| **Top-k** | Число лучших результатов поиска, передаваемых дальше. В проекте `rag.top_k: 10`; это 10 чанков, а не 10 документов. |
| **Group-by-source (группировка по источнику)** | Агрегация чанков по документу-источнику: группы формируются по `(source_type, source_id)`, документы ранжируются по лучшему или суммарному score, в контекст берётся ограниченное число чанков от каждого документа. Защищает от того, чтобы один длинный документ занял весь top-k. В Qdrant — `query_points_groups`/`group_by`; допустима клиентская группировка по полям `SearchResult`. |
| **MMR (Maximal Marginal Relevance)** | Итеративное переранжирование, балансирующее релевантность запросу и новизну относительно уже выбранных результатов: `λ·sim(d, q) − (1−λ)·max sim(d, s)`. Снижает дублирование и overlap-клоны; требует векторов кандидатов. При λ=1 работает как обычное ранжирование, при λ=0 — только разнообразие; типично 0,6–0,8. Не заменяет reranker и может снижать точность на вопросах к конкретному пункту. |
| **Гибридный поиск** | Сочетание dense-поиска (эмбеддинги) и sparse/полнотекстового (BM25) с объединением результатов, например через RRF. Повышает устойчивость к точным идентификаторам: ГОСТ, коды, номера пунктов. В текущей реализации отсутствует; предусловие FR-040/FR-041 (`docs/design-decisions.md` §18). |
| **Reranker** | Модель или шаг, переранжирующий расширенный пул кандидатов (например, top-50) и оставляющий top-k для LLM. Может быть cross-encoder или LLM-listwise. В текущей реализации отсутствует. |
| **Eval-набор (golden set)** | Фиксированный набор запросов с ожидаемыми источниками и фрагментами для измерения качества retrieval и ответов; в проекте планируется `tools/llm_eval` на Этапе 7. |
| **Recall@k** | Доля запросов, для которых правильный источник или фрагмент попал в top-k. |
| **MRR (Mean Reciprocal Rank)** | Среднее обратных рангов первого правильного результата; чувствителен к позиции первого попадания. |
| **nDCG** | Метрика качества ранжирования с учётом позиций и градаций релевантности; применяется для сравнения вариантов retrieval и reranking. |
| **Groundedness** | Доля утверждений ответа LLM, подтверждённых извлечёнными фрагментами; мера опоры на контекст, а не на параметрическую память модели. |
| **ACL-фильтрация RAG** | Ограничение выдачи по правам ДЛ (должности, папки, назначения) через payload-фильтры Qdrant. В текущей реализации не enforced; FR-041 — planned. |
| **Alias-swap** | Атомарное переключение alias Qdrant на новую коллекцию: индекс строится рядом и подменяется целиком. Позволяет переиндексировать без пустого индекса и без delete-then-insert в рабочей коллекции. |

## Аббревиатуры проекта и инфраструктуры

| Аббревиатура | Расшифровка | Пояснение |
|---|---|---|
| **API** | Application Programming Interface | Интерфейс взаимодействия сервисов; в проекте — HTTP API RAG-сервиса. |
| **BM25** | Best Matching 25 | Функция полнотекстового ранжирования; sparse-часть гибридного поиска. |
| **CAS** | Content-Addressed Storage | Хранилище с адресацией по хешу содержимого; см. «CAS-хранилище». |
| **CI** | Continuous Integration | Непрерывная интеграция; GitHub Actions. |
| **FR** | Functional Requirement | Функциональное требование в `requirements.yaml`. |
| **GC** | Garbage Collection | Сборка мусора: удаление объектов без ссылок; см. «GC корпуса». |
| **HTTP/HTTPS** | HyperText Transfer Protocol (Secure) | Протокол взаимодействия 1С с RAG/LLM. |
| **JSON** | JavaScript Object Notation | Формат обмена данными и ответов LLM. |
| **JSONL** | JSON Lines | Формат «один JSON-объект на строку»; используется для манифеста и журналов корпуса. |
| **LLM** | Large Language Model | Большая языковая модель; DeepSeek, GigaChat, локальная модель. |
| **MIME** | Multipurpose Internet Mail Extensions | Тип содержимого файла (`application/pdf` и т.п.); проверяется при записи в корпус. |
| **MMR** | Maximal Marginal Relevance | Переранжирование с балансом релевантности и новизны; см. «MMR». |
| **MRR** | Mean Reciprocal Rank | Среднее обратных рангов первого правильного результата; метрика retrieval. |
| **MVP** | Minimum Viable Product | Минимально жизнеспособный продукт. |
| **nDCG** | normalized Discounted Cumulative Gain | Метрика ранжирования с учётом позиций и градаций релевантности. |
| **NFR** | Non-Functional Requirement | Нефункциональное требование. |
| **OCR** | Optical Character Recognition | Распознавание текста; Tesseract для окна 1С. |
| **RAG** | Retrieval-Augmented Generation | Генерация с поиском по внешнему индексу; Qdrant + эмбеддинги. |
| **RBAC** | Role-Based Access Control | Ролевое управление доступом; роли расширения. |
| **RPO** | Recovery Point Objective | Допустимый объём данных, теряемых при сбое; для корпуса не гарантируется (R2 исключён), для снапшота — 0. |
| **RRF** | Reciprocal Rank Fusion | Объединение ранжированных списков; используется в гибридном поиске. |
| **RTO** | Recovery Time Objective | Допустимое время восстановления; каталоги 1С пересоздаются из снапшота, для корпуса не гарантируется (R2 исключён). |
| **SHA-256** | Secure Hash Algorithm, 256 bit | Криптографический хеш (64 hex-символа); адрес блоба и проверка целостности в CAS. |
| **SQL** | Structured Query Language | Язык запросов к PostgreSQL. |
| **SSRF** | Server-Side Request Forgery | Атака через запросы к внутренним адресам; в R7 запрещены `localhost` и приватные диапазоны. |
| **TLS** | Transport Layer Security | Шифрование HTTP-трафика. |
| **UUID** | Universally Unique Identifier | Уникальный идентификатор объектов метаданных и записей. |

# Анализ вариантов реранкера для RAG-сервиса

Дата: 2026-11-05
Статус: рабочая техническая записка; решение по MVP зафиксировано в `plans/2026-11-04-effective-rag.md` (D17).

## 1. Контекст

RAG-сервис отдаёт кандидатов через `/v1/retrieve`: hybrid dense + sparse BM25, fusion RRF, group-by-source. Финальный порядок можно улучшать реранкером.

Требования к реранкеру:

- качество на русском языке;
- разумная задержка в интерактивном Q&A;
- возможность работы в РФ без VPN;
- приемлемая стоимость;
- желательно отсутствие передачи документов внешнему вендору;
- совместимость с текущим интерфейсом `Reranker` в `rag-service`.

## 2. Текущий baseline

Локальный cross-encoder `BAAI/bge-reranker-v2-m3-int8` на CPU показал:

| Режим | Время |
|---|---|
| Hybrid RRF без rerank | ~0,2 с |
| Rerank 50 кандидатов | ~38 с |
| Rerank 20 кандидатов | ~11 с |

Следствие: для MVP локальный rerank на CPU выключен (`rerank_enabled: false`). Hybrid RRF остаётся быстрым baseline.

## 3. Ключевое ограничение: контекстное окно

Реранкер оценивает пару «запрос + фрагмент». Для cross-encoder это обычно один вход:

- BERT/RoBERTa: 512 токенов на пару;
- `ruT5-base`: 512 токенов;
- `FRED-T5-1.7B`: относительное внимание без жёсткого позиционного лимита, но модель обучалась на коротких последовательностях; длинный контекст не гарантирован;
- `BAAI/bge-reranker-v2-m3` и Jina v2 multilingual: до 8192 токенов.

Если чанк 300–400 токенов, 512-токенного окна достаточно. Если чанк 600–1000 токенов, BERT/ruT5 будет обрезать фрагмент, что для юридических пунктов опасно. В этом случае нужны:

- более короткие структурные чанки;
- sliding window по фрагменту;
- или long-context реранкер (BGE/Jina).

## 4. Модели Сбера

| Модель | Тип | Параметры | Контекст | Пригодность |
|---|---|---:|---|---|
| `ai-forever/ruT5-base` | T5 encoder-decoder | 222M | 512 | Только после fine-tune: yes/no или listwise |
| `ai-forever/FRED-T5-1.7B` | T5 encoder-decoder | 1.7B | Позиционного лимита нет, но длинный контекст не гарантирован | Экспериментальный listwise на GPU; тяжело для CPU |
| `ai-forever/ruBert-base` | BERT encoder | 178M | 512 | Хорошая база для cross-encoder |
| `ai-forever/ruRoberta-large` | RoBERTa encoder | 355M | 512 | Сильнее ruBert, но медленнее |

Лицензии: `ruT5`, `FRED-T5`, `ruBert`, `ruRoberta` — Apache 2.0.

Особенности:

- `ruT5` и `FRED-T5` — seq2seq, а не готовые cross-encoder. Для reranking их нужно дообучать или использовать генеративный prompt, что медленнее и менее стабильно.
- `ruBert-base` и `ruRoberta-large` — encoder-only; это более естественная база для cross-encoder с головой классификации.

## 5. Модели DeepPavlov

| Модель | Тип | Параметры | Контекст | Пригодность |
|---|---|---:|---|---|
| `DeepPavlov/rubert-base-cased` | BERT encoder | 180M | 512 | Хорошая база для cross-encoder |
| `DeepPavlov/rubert-tiny2` | BERT encoder | 29M | 512 | Быстрый coarse-reranker; качество ниже |

Готового официального cross-encoder reranker для русского у DeepPavlov нет. Это базовые MLM/encoder-модели; для качественного reranking нужен fine-tune.

## 6. Готовые мультиязычные реранкеры

| Модель | Контекст | Плюсы | Минусы |
|---|---:|---|---|
| `BAAI/bge-reranker-v2-m3` | 8192 | Сильное качество, multilingual, уже используется локально | На CPU медленно (38 с на 50) |
| `jina-reranker-v2-base-multilingual` | 8192 | Хорошее качество, простой API | Из РФ напрямую недоступен; оплата не в рублях |
| Cohere Rerank | 4096+ | Сильный SaaS | Дороже, доступ/оплата из РФ проблемные |
| Voyage rerank-2 | 8192 | Хорошее качество | Нет рублевой оплаты |
| `mmarco-mMiniLMv2-L12-H384` | 512 | Лёгкий multilingual cross-encoder, потенциально быстрее BGE | Качество на русском нужно проверить; 512 контекст |

## 7. Облачная доступность и оплата из РФ

Проверка из текущего окружения 2026-11-05:

| Сервис | HTTP-ответ |
|---|---|
| `api.jina.ai` | 451 Unavailable For Legal Reasons |
| `r.jina.ai` | 451 |
| `api.cohere.com` | 403 |
| `api.voyageai.com` | 403 |
| `api.openai.com` | 403 |

Вывод: **Jina/Cohere/Voyage напрямую из РФ без VPN/прокси не работают**. Рублевой оплаты у них нет; нужна иностранная карта/юрлицо.

Ориентировочная цена Jina Reranker v2: **$0,02–0,05 за 1M input-токенов** (по сторонним трекерам; официальная страница из РФ недоступна). Для 20–50 фрагментов по ~300 токенов это примерно **$0,0003–0,0008 за запрос**.

Cohere Rerank ориентировочно **около $2 за 1000 поисков** (поиск — запрос до 100 документов); точную цену проверять в кабинете.

## 8. Рекомендация для MVP

Использовать **DeepSeek listwise-реранк** в 1С:

1. `/v1/retrieve` возвращает кандидатов.
2. `АИС_ОтветПоБазеЗнаний` отправляет кандидатов в DeepSeek с промптом `РеранкФрагментов`.
3. DeepSeek возвращает `ranking`.
4. При ошибке/некорректном JSON используется исходный порядок RRF.
5. Citations валидируются по `source_id` и пунктам.

Плюсы:

- нет GPU;
- нет нового вендора;
- работает в рублях через доступный API;
- дешевле отдельного облачного reranker на малых объёмах;
- fallback на RRF сохраняет работоспособность.

Минусы:

- дополнительный вызов LLM на каждый вопрос;
- качество listwise нужно измерить на golden set;
- задержка зависит от DeepSeek.

## 9. Рекомендация для production

Приоритет:

1. **On-prem GPU** с `BAAI/bge-reranker-v2-m3` — лучшее качество и 8192 контекста, данные не уходят.
2. **Yandex Cloud GPU** — рубли, данные в РФ, но оплата простоя и время подъёма.
3. **Selectel GPU** — аналогично, если есть подходящая конфигурация.
4. **Intellion** — у заказчика есть оплаченный аккаунт; использовать как площадку для GPU-эндпоинта.
5. **Jina/Cohere** — только если допустимы VPN/прокси и иностранная оплата.

Если GPU недоступен, следующий кандидат — **дообученный cross-encoder** на `ai-forever/ruBert-base` или `DeepPavlov/rubert-base-cased`:

- 512 токенов;
- чанки 300–400 токенов;
- hard negatives из hybrid top-20;
- 5–20 тыс. обучающих пар;
- оценка nDCG@10 на golden set.

`ruT5-base` и `FRED-T5` не рекомендуются как первый выбор: seq2seq медленнее, а контекст не даёт преимущества. `FRED-T5-1.7B` имеет смысл только как экспериментальный listwise на GPU.

## 10. Что уже реализовано

- `АИС_ИнтеграцияСRAG` — поиск и health.
- `АИС_ОтветПоБазеЗнаний` — контекст, citations, «не найдено».
- Промпт `РеранкФрагментов` — DeepSeek listwise.
- Fallback на RRF при ошибке реранка.
- Локальный cross-encoder отключён в `config/parameters.yaml`.
- Пилот: 30 PDF, 2023 чанка, 1115 с `clause`, 150 табличных чанков.

## 11. Следующие шаги

1. Собрать golden set 60–80 вопросов по типам документов.
2. Сравнить на нём:
   - hybrid RRF без rerank;
   - DeepSeek listwise;
   - (если появится доступ) Jina/Cohere;
   - (если появится GPU) BGE reranker.
3. Замерить nDCG@10, Recall@10, citation accuracy, latency p95 и стоимость.
4. Если listwise даёт недостаточный прирост — переходить к on-prem/GPU или fine-tune ruBert.
5. Отдельно решить аудит Q&A: `АИС_ИсторияДействийИИ` подчинён регистратору, нужен корректный механизм записи.

| Поле | Значение |

## 1. Проблема

Сотрудники тратят время на поиск прецедентов и подготовку черновиков документов; знания о типовых формулировках не формализованы; действия ИИ (если применяются) не имеют единого аудита и контроля. Классический документооборот хранит документы и маршруты, но не анализирует смысл текста.

## 2. Цель

Разработать ПО для автоматизированного анализа неструктурированных документов и подготовки проектов решений в 1С:Документооборот, обеспечивающее интерпретируемый результат (источники и цитаты) и контроль изменяющих действий.

## 3. Реализованный алгоритм

Гибридный поиск (плотные и разреженные представления, переранжирование) + генерация ответа с цитатами + агентный цикл: один шаг за запрос, инструменты выполняются в 1С, изменяющие действия проходят approval или разрешённое автоодобрение, каждый вызов фиксируется в истории. Целевое развитие — шаблоны с плейсхолдерами и поиском по корпусу с фильтрами вместо жёстких ссылок между полями.

## 4. Результат

Работающее расширение 1С с подсистемой «ИИ-Помощник» и сервисами `agent-service`, `search-service`, RAG:

- очередь запусков и инструменты агента;
- approval, временное автоодобрение, таймауты и взаимодействия;
- история действий с колонкой «Пользователь» и сортировкой по дате и пользователю;
- настройки агента и триггеры, монитор запусков, административные экраны;
- RAG-поиск по документам и знаниям, цитаты, поиск внешних образцов;
- папки документов, шаблоны, оргструктура;
- накопление синтетического корпуса для RAG и будущих шаблонов.

Это MVP целевой системы. В целевой модели агент собирает документ по шаблону: структура и плейсхолдеры, для каждого — источник и фильтры поиска. Автоодобрение в целевой системе отсутствует.

## 5. Оценка

Набор из 70 кейсов (60 отвечаемых, 10 без ответа), top-k = 10:

| Метрика | Значение |
|---|---:|
| Recall@10 | 1,00 |
| Citation precision | 0,88 |
| Correctness | 0,94 |
| Groundedness | 0,95 |
| No-answer precision / recall | 0,91 / 1,00 |
| E2E p50 / p95 | 3,18 с / 6,22 с |

Ограничения: курируемый набор, судья на той же модели, демонстрационный корпус; метрики подтверждают работоспособность подхода, но не промышленное качество.

## 6. Практическая значимость

Сокращение времени поиска и подготовки черновика, повышение контролируемости действий ИИ, аудит «кто — что — когда — с каким результатом». Пригодно для пилота в частном контуре с обязательной выборочной проверкой.

## 7. Ограничения и направления развития

Не реализованы: целевые шаблоны с поиском и фильтрами, регламентный триггер по должностным обязанностям, маскирование PII, мастер шаблонов, глубокая вычитка, отчёты. Автоодобрение — временный режим MVP, в целевой системе его быть не должно. Внутренний и входящий документ должны обрабатываться как одно событие; тип документа — атрибут источника. Не зафиксированы: лицензия, поддержка/SLA. Не подтверждена совместимость с 1С:ДО 3.0. Эти пункты вынесены в дорожную карту P0–P2.

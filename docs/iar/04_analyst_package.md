## 2. Что входит в комплект ИАР

1. **Паспорт ИАР** — 1–2 страницы.
2. **Пояснительная записка** — полный текст с приложениями.
3. **Презентация** — PDF, 30 слайдов.
4. **Сценарий демонстрации** — 1–2 страницы.
5. **Реестр артефактов** — этот документ.

## 3. Ключевые артефакты и статус

| Артефакт | Статус | Комментарий |
|---|---|---|
| Требования и матрица | Актуальны | 110 требований; часть post-MVP в статусе `planned` |
| C4 и процессные диаграммы | Актуальны | Целевые и фактические разделены; 25 диаграмм проверены рендером |
| Модель данных | Актуальна | 17 перечислений, 25 справочников, 9 регистров и др. |
| Протокол агента | Актуален | Approval, автоодобрение, версии, ошибки |
| Оценка RAG | Актуальна | 70 кейсов; ограничения указаны |
| Тестовые сценарии | Частично | Ручные сценарии; автоматизация — в развитии |
| PII-маскирование | Отсутствует | P0-риск, вынесен в направления развития |
| Целевые шаблоны | Проект | Плейсхолдеры + поиск с фильтрами |
| Регламентный триггер | Отсутствует | Таймер по должностным обязанностям |
| Автоодобрение | Временный режим MVP | В целевой системе отсутствует |
| Лицензия и поддержка | Не зафиксированы | P0-риск для поставки |

## 4. Как читать статусы требований

В матрице трассируемости статус `planned` означает целевую реализацию, а не факт наличия кода. Поэтому для ИАР в записке приведены только те возможности, которые подтверждены кодом и демонстрацией; остальные отмечены как проект или направление развития.

## 6. Ограничения реестра

Реестр не заменяет исходные документы и не подтверждает юридическую значимость. Для защиты используются актуальные версии из репозитория; при расхождении приоритет имеет код и матрица требований.

## Как построен датасет

1. **Выгрузка чанков.** Scroll всей коллекции с payload:
   `source_id`, `doc_type`, `title`, `clause`, `text`, `page_start`,
   `page_end`, `chunk_index`, `section_path`, `kind`, `active`.
2. **Отбор кандидатов.** Для каждого `doc_type` выбраны документы и по одному
   фактически насыщенному чанку: исключены оглавления, колонтитулы, выходные
   данные, списки нормативных ссылок, формы без содержания и навигационные
   блоки. Для крупных типов (ГОСТ, учебные пособия, руководства, ФЗ) взято
   несколько документов.
3. **Формулировка вопросов.** Вопросы написаны по-русски вручную по тексту
   выбранного чанка, без дословного копирования. Часть вопросов содержит точные
   номера ГОСТ, статей, пунктов и числовые значения.
4. **Автоматическая валидация.** Для каждого answerable-кейса проверено:
   - `source_id` существует в коллекции;
   - `clause`, если он указан, существует в метаданных чанка этого документа;
   - `expected_pages` соответствует странице выбранного чанка;
   - вопрос не содержит длинного дословного n-грамма из текста чанка;
   - числовые значения из `notes` присутствуют в тексте выбранного чанка;
   - `notes` семантически поддержаны чанком (доля совпавших основ слов ≥ 0,9;
     для всех 108 answerable-кейсов проверка пройдена).
5. **Ручной аудит.** После первых прогонов сверены все кейсы с низким
   `correctness`; исправлены 7 дефектов разметки: слишком широкие `notes`
   (домашняя обработка), неоднозначный вопрос про сечение проводника,
   неверное числовое значение в `notes` (клеевые швы), неоднозначный `clause`
   у ФСБУ 6/2020, неоднозначный вопрос про протраву, лишняя формулировка в
   `notes` про клеевые материалы и слишком широкий вопрос по ЕТКС.
6. **No-answer.** 17 вопросов про внутренние факты конкретных организаций
   (`ООО «Альфа»`, `ООО «Ромашка»`, `компания «Вектор»`, `«Чайный дом»`) и про
   документы, отсутствующие в корпусе (ТР ТС 022/2011, ГОСТ Р 52872-2019,
   программа «Приоритет-2030»). Для них проверено отсутствие ключевых
   сущностей/реквизитов в корпусе; `filters` пустые, `expected_*` пустые.

## Проверка expected source/clause

- `expected_source_ids` — `sha256` документа из манифеста, совпадает с
  `source_id` чанков коллекции.
- `expected_clauses` берутся только из поля `clause` реального чанка. Для
  документов без нумерации пунктов (каталоги, руководства, научные статьи,
  часть таблиц) оставлен только `source_id`.
- `expected_pages` — страница выбранного чанка; используется для аудита, не для
  matching в eval.
- Для 108 answerable-кейсов ответ проверен по тексту проиндексированного чанка,
  а не по заголовку или оглавлению.
- Важная оговорка: `clause` в коллекции не всегда уникален внутри документа
  (например, несколько чанков с `пункт 2`). Поэтому clause-совпадение в eval
  может быть выполнено другим чанком того же документа. Это ограничение
  разметки и chunker'а, а не датасета; подробнее — в отчёте.

## Схема записи

```json
{
  "query": "текст вопроса",
  "doc_type": "тип документа",
  "filters": {"doc_types": ["тип документа"]},
  "expected_source_ids": ["sha256 документа"],
  "expected_clauses": ["пункт/статья"],
  "expected_pages": [3],
  "answer_type": "fact | list | process | explanation",
  "must_cite": true,
  "no_answer": false,
  "difficulty": "easy | medium | hard",
  "notes": "краткие эталонные факты для judge"
}
```

Для no-answer: `doc_type` пустой, `filters` пустые, `expected_*` пустые,
`no_answer=true`.

## Воспроизведение оценки

Секреты читаются из абсолютных путей и не коммитятся:

```bash
# retrieval, последовательно (чистая latency)
set -a
. /home/igorvolk/PycharmProjects/ai_scrivener/rag-service/.env
set +a
uv run --project rag-service python -m rag_service.eval \
  --dataset rag-service/eval/golden/knowledge_full.jsonl \
  --top-k 10 \
  --output artifacts/rag-eval/knowledge-full-retrieval.json

# answer + judge, DeepSeek, без GigaChat и без кэша
uv run python -m tools.llm_eval \
  --dataset rag-service/eval/golden/knowledge_full.jsonl \
  --concurrency 4 \
  --no-cache \
  --env-file /home/igorvolk/PycharmProjects/ai_scrivener/.env \
  --rag-env-file /home/igorvolk/PycharmProjects/ai_scrivener/rag-service/.env \
  --output artifacts/llm-eval/knowledge-full-answer-eval.json
```

## Известные ограничения

- 67 типов, а не 68; 4 типа без содержательного текста.
- Для малых типов — один кейс; статистика по такому типу нестабильна.
- OCR-артефакты (`￾`, разорванные слова, слипшиеся числа) в части документов.
- `clause` не уникален внутри документа; возможны ложные clause-совпадения.
- В некоторых юридических документах (ГК, АПК) чанки смешаны с судебной
  практикой и справочными вставками; такие документы не использовались для
  answerable-кейсов, кроме чистых статей ТК РФ.
- Датасет — снимок коллекции; после переиндексации требуется перепроверка.

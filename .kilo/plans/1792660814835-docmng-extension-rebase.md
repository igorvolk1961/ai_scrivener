# План: перевод ai_scrivener на расширение 1С:Документооборот 2.1.38.11

## 1. Цель и границы

Создать расширение 1С:Документооборот 2.1.38.11 и подготовить локальный стенд из выгрузки `.dt`. Обновить документацию, требования, EDT-проект и проверки так, чтобы расширение собиралось, применялось к демо-базе и проходило сквозной сценарий MVP.

В границах:

- локальный стенд на 1С:Предприятие 8.3.27 Community;
- база из `DocMng_2_1_38_11_new.dt`;
- расширение `.cfe`, не изменяющее конфигурацию базы;
- переиспользование штатных объектов Документооборота;
- RAG-сервис и DeepSeek без изменения архитектуры.

Вне границ:

- коммерческая лицензия на 1С:Документооборот и production-эксплуатация;
- дообучение LLM, электронная подпись, HA, мобильный клиент;
- поддержка обеих редакций и обеих версий базы по умолчанию.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Демо-база окажется ПРОФ, а не КОРП | Маппинг строится по факту; не использовать объекты, которых нет |
| Демо-режим ограничивает число пользователей/операций | Зафиксировать лимиты; RLS-тесты по возможности на одном пользователе + негативные проверки |
| Конфигурация базы защищена | Проверить создание расширения до начала работ; при запрете — согласовать с преподавателем |
| Режим совместимости базы ниже 8.3.27 | Установить режим расширения равным базе, не «8.3.27 по умолчанию» |
| Расширение не может добавить RLS к базовым документам | RLS только на новых `АИС_*` объектах; базовые документы — штатные права |
| Дублирование объектов базы | Жёсткое правило: сначала инвентаризация, потом `reuse/extend/new` |
| Случайная фиксация `.dt`/`.cf`/`.cfe` | `.gitignore` + проверка `git status` перед коммитом |
| Ограничения community-лицензии | В README явно указать: учебный/демо-стенд, не production |

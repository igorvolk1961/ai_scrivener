## Быстрый запуск

```bash
export ONEC=/opt/1cv8/x86_64/8.3.27.2342/1cv8
export IB=/home/igorvolk/1C/ai_scrivener_docmng

"$ONEC"                       # окно запуска 1С
"$ONEC" DESIGNER /F"$IB" /N Администратор   # Конфигуратор
"$ONEC" ENTERPRISE /F"$IB" /N Администратор # 1С:Предприятие

bash scripts/run/1c.sh        # то же через обёртку; запускать bash, не sh
bash scripts/run/1c.sh designer
bash scripts/run/1c.sh enterprise
bash scripts/run/1c.sh check

bash scripts/run/1c.sh pg-enterprise  # серверная база PostgreSQL
bash scripts/run/1c.sh pg-designer
bash scripts/run/1c.sh pg-db          # psql к базе 1С
bash scripts/run/1c-pg-server.sh      # PostgreSQL + кластер 1С в одном терминале
bash scripts/run/1c-pg-server.sh stop # остановить PostgreSQL и кластер

./scripts/build/export_extension.sh   # src → EDT-копия → XML
./scripts/build/load_extension.sh server # XML → серверная база
```

Пользователь базы — `Администратор`, пароль пустой. Подробная инструкция со всеми путями, EDT, расширением и RAG — в `guides/runbook.md`.

Десктопный клиент 1С нельзя водить программно (нет инструмента ввода) — клики там делает человек. Для автоматических UI-проверок (разные пользователи, роли, права) та же база поднимается как веб-клиент через автономный сервер `ibsrv` и управляется Playwright без участия человека — `guides/runbook.md` §2.5.

## Статус

Сформированы требования, матрица трассируемости, конфигурация числовых параметров и пре-коммит-проверки. Реализована инфраструктура RAG-сервиса (naive RAG): FastAPI, GigaChat Embeddings (`EmbeddingsGigaR`, 2560), Qdrant, API индексации и поиска, тесты. Проверен сценарий на 3 шаблонах — поиск вернул релевантный первым; это подтверждает работу инфраструктуры на маленьком корпусе, а не качество поиска в целом. Известные ограничения подхода (чанкинг без учёта структуры, отсутствие гибридного поиска и reranker, неоткалиброванный confidence LLM) задокументированы в `reviews/critical-review.md` §3 и не устранены — решено исправлять по мере роста корпуса шаблонов (`docs/design-decisions.md` §18), не сейчас.

Проект разрабатывается как расширение 1С:Документооборот 2.1.38.11, редакция ПРОФ (`ДокументооборотПРОФ`). Лицензия 8.3.27 активирована, демо-база `DocMng_2_1_38_11_new.dt` восстановлена в файловую базу и в серверную базу PostgreSQL (`ai_scrivener`, 1363 таблицы). Базовая конфигурация импортирована в EDT. Метаданные Этапа 2 в основном созданы и проверены реальной сборкой через EDT CLI: 8 перечислений, 8 справочников расширения (включая `АИС_Промпты`, `АИС_РазделыДокумента`, `АИС_ЛистОжидания`, `АИС_РасписаниеТриггеров` — справочники, не регистры, см. `docs/data-model.md`), 4 регистра сведений, 5 ролей, параметр сеанса `АИС_ТекущееДЛ` и общие модули `УстановкаПараметровСеанса`, `АИС_Промпты`, `АИС_ОбщегоНазначения`, `АИС_Сотрудники`, `АИС_Уведомления`; константы `АИС_КлючИИ`/`АИС_МодельИИ`. ТЧ `АИС_Плейсхолдеры` добавлена в три штатных справочника шаблонов, `Справочник.ИсточникиДанных` расширен реквизитами URL, JSON-схема и таймаут, `Справочник.ВнутренниеДокументы` — реквизитами `АИС_Должность`, `АИС_ИспользованШаблон`, `АИС_ДополненоРазделами`, `АИС_СтатусСогласованияБухгалтера` и ТЧ `АИС_ЗапрашиваемыеДолжности`; RLS настроен по базовой задаче. EDT build/validate проходят без ошибок, остаются только minor style warnings. Базовые должности, сотрудники и последовательность приказов собственника настраиваются в симуляторе (`config/enterprise.json` и его UI); расширение не создаёт базовые данные. Начальные тексты промптов — `АИС_Промпты.Заполнить()` или HTTP `POST /hs/ais-sim/prompts/seed`. Негативные сценарии доступа (`tests/1c/test_access.md`) частично пройдены.

На 2026-10-26 в расширении уже реализована часть прикладной логики: общие модули `АИС_Сотрудники` (найм и роли), `АИС_ОбщегоНазначения` (задачи, поиск шаблонов, иерархия, `ВызватьИИ`, черновик шаблона), `АИС_Уведомления` (адресные документы, HR-шлюз на заявку найма, автошаблонизация), подписка `АИС_ВнутреннийДокументПриЗаписи`, HTTP-сервис `АИС_Симулятор`, обработка `АИС_Оргструктура` с прямым UI для просмотра дерева подразделений и персональной подчиненности, а также обработка `АИС_Шаблоны` — прямой список шаблонов внутренних, входящих и исходящих документов с текстом и встроенным редактированием статуса/текста в «АИС: Сервис». Администратор и Программист 1С имеют права на редактирование шаблонов. Тексты промптов хранятся отдельно в `АИС_Промпты`, параметры — в `АИС_ПромптПараметры`; автошаблонизация читает активный промпт `ФормированиеШаблонаПоДокументу` из базы, а не из кода. Полный оркестратор (триггеры → задача → черновик → верификация), разрешитель плейсхолдеров, остальные формы и регламентные задания остаются Этапами 4–6, подробности в `plans/stage2-plan.md` и `plans/2026-10-26-enterprise-simulator.md`.

Отдельный симулятор предприятия (`ai-scrivener-enterprise-sim`) выращивает демонстрационный корпус документов и пользователей силами LLM-агентов, играющих роли сотрудников. Предопределённые должности: `ГенДиректор`, `ГлавныйИнженер`, `ГлавныйБухгалтер`, `ДиректорПоПерсоналу` и `Программист1С`; последний технически согласует черновики шаблонов, окончательно их утверждает автор документа, а оргструктуру программист ведёт по распоряжению CEO. Проверены HTTP-сервис найма/документов/задач, автоматический поиск шаблонов на стороне расширения, автошаблонизация по готовому документу, HR-шлюз с согласованием зарплатной вилки Главным бухгалтером и агенты Главного инженера, HR, Главного бухгалтера и Программиста 1С. HTTP-сервис — тестовый адаптер: в штатной работе без симулятора используются штатные механизмы 1С:Документооборота, а расширение обрабатывает их своими подписками и AI-контуром. Известные пробелы зафиксированы в плане: агентские инструменты пока не передают `ЗапрашиваемыеДолжности` и `Должность` для должностных инструкций, поэтому заявка на найм и инструкции в части сценариев создаются вручную через API.

Проектирование завершено: решения по шаблонам, сравнению, разделам, вычитке и квотам зафиксированы в `docs/design-decisions.md`; решения по симулятору и кадровому контуру — в `docs/design-decisions.md` §19 и `plans/2026-10-26-enterprise-simulator.md`.

Полный порядок запуска платформы, базы, Конфигуратора, EDT, расширения и RAG-сервиса — в `guides/runbook.md`.
